# 第 6 部分：新 ESP32-CAM 独立验收

- 本次范围：只验收新到货的 ESP32-CAM 和新 ESP32-CAM-MB，不测试电机系统

- 用户现场确认新模块的型号、丝印、插针和摄像头方向与原模块一致。

- 按用户要求跳过商家预装热点固件检查，直接烧录仓库现有的 1.5 秒限时测试固件。

商家热点名称、密码 `12345678` 和 `192.168.4.1` 只适用于可能存在的商家预装固件，不作为烧录成功的判据。

## 固件与工具

- PlatformIO 环境：`esp32cam`
- 目标板：AI Thinker ESP32-CAM
- 串口：`/dev/cu.usbserial-10`
- 编译与烧录速度：烧录 `115200`，串口监视 `115200`
- 测试固件：仓库现有四电机自动测试程序，每个动作限制为 `1.5 s`

测试期间四路 GPIO 没有连接驱动板，因此程序中的动作日志只用于确认固件执行流程，不代表电机实际动作。

| 固件执行 | 通过 | 串口完整打印左右侧、双侧和两种原地转向组合的 8 个限时步骤；每步均打印停止，最后报告所有输出保持禁用 |

第一次编译尝试因受限运行环境无法写入 PlatformIO 用户缓存和锁文件而停止，尚未进入源码编译。允许 PlatformIO 使用其现有用户目录后重新编译成功；该权限错误不属于固件编译失败。

## 与旧模块异常的边界

旧 ESP32-CAM 仍能执行旧程序并控制闪光灯，但配合两块下载板均多次出现 esptool `No serial data received`，复位串口也曾出现大量空字符或乱码。现有证据只能说明旧模块的 UART、GPIO0、供电或相关硬件部分存在故障嫌疑，不能确定具体损坏点。

新模块使用新 ESP32-CAM-MB 一次完成芯片识别、写入校验和清晰串口启动，说明本次新模块与新下载板组成的下载和串口链路工作正常；这不能单独证明旧下载板损坏或正常。

- AA 电池盒保持为空，驱动板没有通电。
- 新 ESP32-CAM 尚未连接四路 GPIO、公共地、面包板或电机系统。
- 本记录不把固件日志表述为四电机实机动作通过。

## 后续边界

下一阶段开始前，仍需在完全断电状态下逐个核对 GPIO12、GPIO13、GPIO14、GPIO15 和公共地的实际落点，并复查两套电源正极相互独立。只有这些断电检查通过后，才能讨论电机系统的受控通电验证。
