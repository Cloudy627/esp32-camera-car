## 与旧模块异常的边界

旧 ESP32-CAM 仍能执行旧程序并控制闪光灯，但配合两块下载板均多次出现 esptool `No serial data received`，复位串口也曾出现大量空字符或乱码。现有证据只能说明旧模块的 UART、GPIO0、供电或相关硬件部分存在故障嫌疑，不能确定具体损坏点。

新模块使用新 ESP32-CAM-MB 一次完成芯片识别、写入校验和清晰串口启动，说明本次新模块与新下载板组成的下载和串口链路工作正常；这不能单独证明旧下载板损坏或正常。

## 2026-08-26 四电机接线与断电检查

新 ESP32-CAM 暂不固定，平放在绝缘垫上，使用母对公杜邦线连接低电流控制信号：

| ESP32-CAM | 面包板位置 | 功能 |
| --- | --- | --- |
| GPIO13 | 第 15 行左半区 | 左侧方向输入 1 |
| GPIO14 | 第 17 行左半区 | 左侧方向输入 2 |
| GPIO12 | 第 19 行左半区 | 右侧方向输入 1 |
| GPIO15 | 第 21 行左半区 | 右侧方向输入 2 |
| GND | 第 25 行左半区 | 与两块驱动板共地 |

- ESP32-CAM 使用独立两芯 USB 线从充电宝供电，红线接 `5V`，黑线接相邻的 `GND`。
- 两芯 USB 线空载测得约 `+5.1 V`；排查期间在 ESP32-CAM 的 `5V`—`GND` 焊点测得 `+5.15 V`。
- 用户确认 ESP32-CAM GND 到 TC1508A 电源负极导通。
- 用户确认 ESP32-CAM `5V` 与 TC1508A 电源正极不导通，两套电源正极保持独立。
- 电机电源使用 4 节串联镍氢 AA 电池；启动准备期间只装 3 节，驱动板电源测得接近 `0 V`，最后一节作为测试时的电机电源断开点。
- 四个车轮全部拆除，四根电机输出轴保持空载。

## 首次无响应与接触排查

首次完整接线后上电，用户报告 ESP32-CAM 和四台电机均无反应，白色闪光灯没有按程序闪烁。没有盲目重复上电，而是断电后逐步隔离线路：

1. 模块焊点仍测得 `+5.15 V`，排除外接供电线完全开路或极性接反。
2. 断开 GPIO12 和 GPIO15 后仍未观察到闪光灯动作。
3. 再断开 GPIO13、GPIO14 和控制公共地，仅保留独立 `5V/GND` 供电后，白灯恢复按程序闪烁 5 次，证明新模块、供电和固件仍能启动。
4. 依次恢复控制公共地、GPIO13 和 GPIO14，每次测试均能正常闪灯。
5. 用户重新插接剩余杜邦连接后，完整系统恢复正常，并完成四电机自动测试。

现有证据更符合临时杜邦接头接触不良，但没有定位到唯一松动点，因此不把故障归因到某一个 GPIO、驱动板或 ESP32-CAM。后续固定结构前需要更换或重新压接可疑杜邦线，并增加线束应力释放。

## 四电机实机结果

用户现场报告四台电机均按程序动作，依次完成：

1. 左侧方向 A、停止、左侧方向 B、停止。
2. 右侧方向 A、停止、右侧方向 B、停止。
3. 两侧方向 A、停止、两侧方向 B、停止。
4. 两种相反方向组合，随后最终保持停止。

每次动作约 `1.5 s`，动作间停止约 `2 s`。用户报告过程符合程序、四台电机均有转动且没有其他异常。本次在拆轮空载条件下验证动作和停止，不把方向 A/B 提前命名为车辆前进、后退、左转或右转；实际车辆方向仍需安装车轮后另行确认。
