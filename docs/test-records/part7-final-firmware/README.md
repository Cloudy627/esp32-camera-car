## 手机网页控制

- 按下并保持某个动作按钮时，页面约每 `200 ms` 向 ESP32 续发一次相同命令。
- 松开、触摸取消、按钮失去指针捕获、页面失去焦点或切到后台时，页面结束续发并请求停止。
- 移动请求按顺序完成后再发送停止，减少快速松手时旧移动请求晚于停止请求的可能性。
- 页面另有“立即停止”按钮，并明确显示方向仍需后续机械验证。

## 停车保护

最终固件使用三层互相独立的停车边界：

1. **启动默认停止**：在摄像头和 Wi-Fi 初始化前，先将 GPIO12、GPIO13、GPIO14、GPIO15 配置为输出并保持 LOW。
2. **通信超时停车**：动作期间超过 `500 ms` 未收到有效续发命令，车端自行把四路输出置为 LOW。
3. **单次动作上限**：一次连续动作最多 `1500 ms`；即使网页仍在续发命令，车端也会停车并锁止。收到明确的停止命令后才解除锁止，用户必须松开并重新按住才能开始下一次动作。

动作期间若收到与当前动作不同的移动命令，车端也会先停车并锁止；方向切换必须先经过明确的停止状态，避免交替命令绕过 1.5 秒上限。

网页停止请求不是唯一保护条件。即使浏览器关闭、Wi-Fi 中断或 JavaScript 未成功发出松手命令，车端的通信超时仍会结束旧动作。

## GPIO12 / GPIO15 启动约束

GPIO12 和 GPIO15 是 ESP32 启动配置脚。软件在 `setup()` 开始时尽快写入停止状态，但软件不能消除芯片复位阶段的硬件约束，因此必须继续遵守：

- ESP32-CAM 启动时电机电源必须关闭。
- 只有串口显示摄像头与控制网页就绪后，才可在后续实机测试中接通电机电源。
- 两块 TC1508A 驱动板供电期间不得重启或复位 ESP32-CAM。
